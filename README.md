## いまの状態

**2つのモードがあります。同じURL・同じコードで、設定の有無だけで切り替わります。**

| | 体験版（いまの既定） | 本番 |

## 開くには

**プレビュー： <https://playmark0227-svg.github.io/ezemi-preview/>**
（検索避け済み・URLを知っている人だけが見られます）

手元では `index.html` をダブルクリックすれば動きます（サーバー不要・依存ライブラリなし）。
うまく動かないときは、このフォルダで下を実行して <http://localhost:8765> を開いてください。

```bash
python3 -m http.server 8765
```

| ページ | ファイル | 入りかた |
|---|---|---|
| 公開サイト（HP内に置く想定） | `index.html` | そのまま |
| 会員ページ | `member.html` | デモ用ボタンで即ログイン／パスワードは `demo1234` |
| 管理画面（代表が触るところ） | `admin.html` | パスワード `ezemi` |

初回に開くとデモの会員6名・配信10本が入ります。**管理画面 → データ → 「デモデータを消す」で一括削除**できます。

### 右下の「検証用」バー

日付を +1日 / +1週 / +1ヶ月 と進められます。ここが本番との違いを見てもらう一番早い方法です。
たとえば **+1ヶ月** を押すと、誰も操作していないのに次のことが全部起きます。

- 全員の月額が自動で決済される（入会日を基準に毎月同日）
- カードが通らない会員は自動リトライ → 猶予を過ぎたら自動で閲覧停止
- 解約した会員は期間末で自動的に終了し、会員ページが閉じる
- 1ヶ月を過ぎた配信が自動で非公開になり、「殿堂入り」だけが残る
- 予約投稿がその時刻に自動で公開され、メールとLINEの通知が飛ぶ

**本番ではこの日付操作バーは外します。**

## 直したものを公開に反映するには

GitHub Pages は CSS と JS を10分キャッシュします。直したまま push すると、
先方の画面で古いファイルと新しいファイルが混ざることがあります。**必ず先に版番号を上げてください。**

```bash
./bump.sh && git add -A && git commit -m "修正内容" && git push
```

`bump.sh` は3つのHTMLの `?v=...` を書き換えるだけです。反映まで1〜2分かかります。

## デザインについて

運営会社が同じなので、**知上会コーポレートサイト（`playmark0227-svg/chijokai-site`）と
同じ設計体系**に揃えてあります。色・角丸・影・書体・ボタンの役割分担・カードの形は
あちらの `assets/css/style.css` から写したもので、トークン名も原則そのままです。
**片方を直したら、もう片方も追随させてください。**

- 深海のネイビー（`--deep #0a1c2e`）＋ くすんだ真鍮色（`--gold #b08d4f`）＋ 紙色（`--paper #faf9f7`）
- 見出しは明朝、本文は角ゴシック、英数字は Optima 系
- カードは白い面＋ヘアライン＋左上に真鍮色の短い罫（44px）、角丸10px
- 濃色の面ではボタンが反転する（primary＝真鍮色／ghost＝白い枠線）

ゼミ側は「読み物」に寄せてあります。表紙は全画面ではなく帯に留め、
数字のタイルや3列のカードは置かず、罫線と余白で組んでいます。
金融情報を読み解く場所なので、広告の面ではなく資料の面に見えるほうがよい、という判断です。

**やらないことを決めてあります。**（既製のテンプレートに見えてしまうため）

- 実績でない数字を「◯回」「◯日」のように並べて見せない
- 01 / 02 / 03 の3列カードを使わない
- 同じ装飾（見出し下の罫、カード上端の罫）を全部の要素に繰り返さない
- ホバーで光を走らせる、面を浮かせるといった演出を入れない
- 押しても何も起きない飾りのボタンやタグを置かない
- 最後に全幅の濃色CTA帯で畳みかけない

ロゴ・写真・favicon は本社サイトと共通のものを使っています（`assets/img/CREDITS.md`）。

## 本番の作り

**Firebase Authentication ＋ Firestore**。サーバのプログラム（Cloud Functions）は使っていません。

使わずに済ませた理由は2つあります。ひとつは Cloud Functions が Blaze プラン（カード登録）必須で、
契約前に先方へ負担をお願いすることになるため。もうひとつは、毎月の課金と督促は
**Stripe 側の機能がそのまま持っている**ので、こちらで定期処理を書く必要がないためです。

定期実行なしで成り立たせるために、**状態を保存せず、その場で計算する**作りにしてあります。

| 判定 | どうやっているか |
|---|---|
| 会員資格（有効／終了／停止） | `statusOf()` が、いまの時刻と `periodEnd` を毎回見て決める |
| 配信の掲載期限 | `publishAt` からの経過で決める。期限切れを書き込む処理は無い |
| 予約投稿の公開 | `publishAt` を過ぎたかどうかで決める |
| 講座の解錠 | 前の回の課題があるかどうかで決める |

だから「期限切れを反映するサーバ処理が止まっていて、退会した人がまだ見られる」という
事故が起きません。

### 守り（Firestore のルール）

画面のコードは誰でも読めるので、**守りは `firestore.rules` の1枚に集約**しています。
ここに書いてあること：

- 会員が読めるのは自分の提出物だけ。他の会員のレポートは見えない
- **会員資格（`billing`）は本人に書かせない**。ここが書けると払わずに閲覧を続けられる
- 課題は「前の回を出していないと作れない」。画面の解錠だけだと直接書き込みで素通りする
- 配信は、公開前のもの・掲載期間を過ぎたものを**読ませない**
- 管理画面を開けるのは `admins` に登録した人だけ。`admins` は誰にも書き込めない

### まだ差し替えが要るところ

| いまの実装 | 本番 |
|---|---|
| 決済モーダル（`site.js` の `checkout()`） | Stripe Checkout（入会金＝一回払い＋月額＝サブスク） |
| 会員資格の更新 | Stripe の Webhook から `members/{uid}.billing` を書く |
| `notifyMember()` の送信ログ | 会社ドメインからのメール送信（SPF/DKIM）＋ LINE Messaging API |
| 動画URL欄 | YouTube 限定公開などの埋め込み（URL直打ちで外から見えないもの） |

### 動作確認

`tools/test-cloud.html?faketest=1` を開くと、本番つなぎの結線を自動で確かめます
（偽の Firebase を差し込んで、入会・解錠・掲載期限・資格判定を通します）。
`tools/` は本番の動きには一切関わりません。

### 引き継ぎについて（仕様書 0-3 / 非機能要件）
- 利用サービス（Firebase・Stripe・LINE）のアカウントは**すべて知上会名義**で作ります。制作者アカウント内に御社データは置きません。
- コードはこのフォルダ一式で完結しています。特殊なビルドツールを使っていないので、第三者がそのまま引き継げます。
- 会員情報・提出物は管理画面から CSV と JSON で書き出せます。
